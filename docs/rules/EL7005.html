EL7005

edifact.interchange-count

Applies to: edifact

What it catches and why it matters

UNZ-1 does not match the recounted messages in the interchange, or the recounted functional groups when UNG groups are used.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

An ungrouped UNB contains one message but ends with UNZ+2+EXAMPLE'.

How to fix it

Set UNZ-1 to the number of messages in an ungrouped interchange, or to the number of functional groups when UNG groups are used.

False positives and limits

Counting messages instead of groups in a grouped interchange causes a mismatch. Confirm the envelope form before changing the trailer.

Acknowledgments and suppression

Related acknowledgment codes (apply only to the described defect):
  CONTRL code 29 (UCI.0085): UNZ-1 differs from the received message or group count
  CONTRL code 13 (UCI.0085): UNZ-1 is missing
  CONTRL code 37 (UCI.0085): UNZ-1 contains letters where digits are required
CONTRL references use syntax-error element 0085, not action element 0083. UCI, UCF and UCM report interchange, group and message service-segment errors respectively. A missing or unreadable header can prevent a valid CONTRL response. Truncation, orphaned envelopes and data outside an interchange have no single mapping here.
Sources: https://service.gefeg.com/jwg1/Archive/v3/mt/m01.htm https://service.gefeg.com/jwg1/Archive/cl/v3/21a/cl16.htm
Suppress the rule with --disable EL7005, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
