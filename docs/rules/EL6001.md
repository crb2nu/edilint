# EL6001 — hl7batch.unclosed

| Class | Severity | Applies to |
|---|---|---|
| hl7batch | error | `hl7v2` |

FHS or BHS is never closed by a matching FTS or BTS, so the batch envelope is incomplete.

## What it catches

An FHS or BHS header that is never closed by its FTS or BTS trailer. Batch-aware readers buffer until the trailer arrives, so an unclosed batch either stalls the reader or is discarded whole once the stream ends.

## Example

`batch.hl7`:

```text
FHS|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000|||NGFILE0001
BHS|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000|||NGBATCH0001
MSH|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000||ADT^A08|NGMSG0001|P|2.5.1
PID|1||NGH900000001^^^NORTHGATE^MR||RIVERA^DANA
FTS|1
```

`edilint batch.hl7` reports:

```text
batch.hl7:2: error: [EL6001 hl7batch.unclosed] BHS is never closed by a matching BTS (record 2, segment BHS)
```

## How to fix

Resend the file. A missing trailer means the sending system did not finish writing the batch, so the messages already in it may not be the full set.

## When to suppress

There is no safe case: an incomplete batch envelope means the receiver cannot tell whether it has every message.

Suppress the rule for a run with `edilint --disable EL6001`, or for a repository by listing it under `disable:` in `.edilint.yml`.
