# EL3011 — envelope.missing-control-id

| Class | Severity | Applies to |
|---|---|---|
| envelope | error | `x12` |

ISA13 interchange control number is empty.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| TA1 | `TA105` | `018` | invalid interchange control number value |

## What it catches

An ISA13 that is blank. The interchange control number is what a receiver acknowledges and what both sides use to trace a file after the fact; an empty one leaves the interchange unidentifiable.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*         *0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
GE*1*1~
IEA*1*         ~
```

`edilint example.x12` reports:

```text
example.x12:1: error: [EL3011 envelope.missing-control-id] ISA13 interchange control number is empty (record 1, segment ISA)
```

## How to fix

Populate ISA13 from the sender's interchange counter and copy the same value into IEA02. The element is fixed-width, so the value is normally zero-padded to nine characters.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL3011`, or for a repository by listing it under `disable:` in `.edilint.yml`.
