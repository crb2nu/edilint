# EL3001 — envelope.isa-length

| Class | Severity | Applies to |
|---|---|---|
| envelope | error | `x12` |

ISA segment is not the fixed 106 characters, or is absent.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| TA1 | `TA105` | `022` | invalid control structure; a receiver that cannot read the ISA often cannot return a TA1 at all and drops the transmission |

## What it catches

An ISA that is not exactly 106 characters, or a file forced to the x12 format with no ISA at all. ISA is the one X12 segment with fixed-width elements, and every element after a short or long one is read from the wrong offset — including ISA16, which declares the component separator the rest of the file is parsed with.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP*260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
GE*1*1~
IEA*1*000000001~
```

`edilint example.x12` reports:

```text
example.x12:1: error: [EL3001 envelope.isa-length] ISA segment is 103 characters including the terminator; X12 fixes it at 106, so every downstream fixed-offset read of the envelope is shifted (record 1, segment ISA)
```

## How to fix

Regenerate the ISA from the envelope data rather than editing it. Each element has a mandatory width, so padding one field by hand tends to move the error rather than clear it.

## When to suppress

There is no safe case. A malformed ISA means every field the receiver reads by offset is suspect.

Suppress the rule for a run with `edilint --disable EL3001`, or for a repository by listing it under `disable:` in `.edilint.yml`.
