# EL1007 — charset.x12-basic

| Class | Severity | Applies to |
|---|---|---|
| charset | warning | `x12 (requires --charset basic)` |

Character outside the X12 basic character set but inside the extended set. Off by default; the default profile is extended.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| 999 | `IK403` | `6` | invalid character in a data element, when the partner accepts only the basic set |

## What it catches

Characters legal in the X12 extended character set but outside the basic set: lower-case letters and the punctuation the extended set adds. The check is off by default because the default profile is extended; it runs under `--charset basic` for partners whose specification still names the basic set.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
N1*PR*Northgate Health~
SE*3*0001~
GE*1*1~
IEA*1*000000001~
```

`edilint --charset basic example.x12` reports:

```text
example.x12:4:8: warning: [EL1007 charset.x12-basic] record contains 13 character(s) outside the X12 basic character set but within the extended set ("o", "r", "t", "h", "g", "a", "e", "l"); pass --charset extended if the partner accepts them (record 4, segment N1)
```

## How to fix

Upper-case the affected content, or drop the punctuation the basic set omits. If the partner in fact accepts the extended set, run without `--charset basic` rather than editing the file.

## When to suppress

The rule only runs when it is asked for, so suppression is a matter of not passing `--charset basic`. Do that once the partner confirms the extended set.

Suppress the rule for a run with `edilint --disable EL1007`, or for a repository by listing it under `disable:` in `.edilint.yml`.
