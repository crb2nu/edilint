EL7004

edifact.group-count

Applies to: edifact

What it catches and why it matters

UNE-1 does not match the recounted messages in the functional group.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

A UNG contains one UNH/UNT message but ends with UNE+2+GROUP1'.

How to fix it

Set UNE-1 to the number of messages in that functional group after checking that all intended messages are present.

False positives and limits

Bad nesting or missing message headers can change the observed total. A corrected trailer count does not prove payload completeness.

Acknowledgments and suppression

Related acknowledgment codes (apply only to the described defect):
  CONTRL code 29 (UCF.0085): UNE-1 differs from the received message count
  CONTRL code 13 (UCF.0085): UNE-1 is missing
  CONTRL code 37 (UCF.0085): UNE-1 contains letters where digits are required
CONTRL references use syntax-error element 0085, not action element 0083. UCI, UCF and UCM report interchange, group and message service-segment errors respectively. A missing or unreadable header can prevent a valid CONTRL response. Truncation, orphaned envelopes and data outside an interchange have no single mapping here.
Sources: https://service.gefeg.com/jwg1/Archive/v3/mt/m01.htm https://service.gefeg.com/jwg1/Archive/cl/v3/21a/cl16.htm
Suppress the rule with --disable EL7004, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
