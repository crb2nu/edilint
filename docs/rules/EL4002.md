# EL4002 — counts.unparsable

| Class | Severity | Applies to |
|---|---|---|
| counts | error | `all (requires --count-rule)` |

The field a count rule points at is not an integer.

## What it catches

A count field that is not an integer: a decimal total, a label, or a field that has drifted one position because the record gained a column. The rule reports the value it read, which is usually enough to see which of those happened.

## Example

`eligibility.psv`:

```text
HDR|NORTHGATE HEALTH|20260115|ELIG
DTL|NGH900000001|RIVERA|DANA|19840322|F|PPO-GOLD|20260101|20261231
DTL|NGH900000042|OKONKWO|TERESA|19770915|F|PPO-GOLD|20260101|20261231
TRL|two
```

`edilint --count-rule TRL:2:DTL eligibility.psv` reports:

```text
eligibility.psv:4: error: [EL4002 counts.unparsable] count rule TRL:2:DTL: field 2 is "two", which is not an integer (record 4, type TRL) https://crb2nu.github.io/edilint/rules/EL4002.html
```

## How to fix

If the field holds a number in another form, point the count rule at the field that holds the record count. If the record gained a column, update the field index everywhere the layout is configured.

## When to suppress

When the extract genuinely has no integer record count. Drop the count rule for that file rather than suppressing the rule.

Suppress the rule for a run with `edilint --disable EL4002`, or for a repository by listing it under `disable:` in `.edilint.yml`.
