# EL2002 — terminator.missing-final

| Class | Severity | Applies to |
|---|---|---|
| terminator | warning | `hl7v2, delimited, fixed, text` |

Last record has no terminator.

## What it catches

A final record with no terminator after it. Streaming readers that split on the terminator either drop the last record or hand it on as a partial one, so the row that goes missing is reliably the last — the hardest kind of loss to notice in a reconciliation.

## Example

`eligibility.psv`:

```text
HDR|NORTHGATE HEALTH|20260115|ELIG
DTL|NGH900000001|RIVERA|DANA|19840322|F|PPO-GOLD|20260101|20261231
```

The file ends immediately after the last record shown, with no terminator after it.

`edilint eligibility.psv` reports:

```text
eligibility.psv:2: warning: [EL2002 terminator.missing-final] last record has no terminator; readers that require a trailing newline will drop or truncate it (record 2, type DTL) https://crb2nu.github.io/edilint/rules/EL2002.html
```

## How to fix

Append the file's terminator after the last record. `edilint fix --write` adds it, using the terminator the rest of the file uses.

## When to suppress

When the receiver is known to accept an unterminated final record, which some CSV readers do. It stays a warning rather than an error for that reason.

Suppress the rule for a run with `edilint --disable EL2002`, or for a repository by listing it under `disable:` in `.edilint.yml`.
