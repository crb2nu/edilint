EL6005

hl7batch.separator

Applies to: hl7v2

What it catches and why it matters

FHS, BHS and MSH headers disagree on the field separator or the encoding characters, or a header's encoding characters are malformed. Split-and-merge tooling reads every message with the first header's separators, so a disagreeing message is misparsed.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

BHS|^~\&
MSH*^~\&*EXAMPLE
  (field separator changes from | to *)

How to fix it

Use consistent declared separators and well-formed encoding characters throughout each enclosing batch/file context. Regenerate payload fields with the same declarations.

False positives and limits

Separately valid messages concatenated under one batch header may disagree. Validate them separately or normalize their serialization before batching; changing only the header is insufficient.

Acknowledgments and suppression

No X12 acknowledgment code names this defect; it is caught by the parser or the hygiene layer before an acknowledgment is produced.
Suppress the rule with --disable EL6005, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
