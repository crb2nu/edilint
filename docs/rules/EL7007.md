# EL7007 — edifact.service-string

| Class | Severity | Applies to |
|---|---|---|
| edifact | error | `edifact` |

UNA is not the fixed nine characters, its service characters collide or are alphanumeric, or its decimal mark is not a period or a comma.

## What it catches

A UNA that is not the fixed nine characters, declares service characters that collide with each other, or names a decimal mark that is neither a period nor a comma. UNA declares the characters the rest of the interchange is parsed with, so a malformed one makes every later segment boundary uncertain.

## Example

`order.edi`:

```text
UNA:+/? '
UNB+UNOA:4+NORTHGATEHEALTH+VALEMEDGROUP+260115:1430+NG260002'
UNH+NG0001+ORDERS:D:96A:UN'
BGM+220+NG77001+9'
UNT+3+NG0001'
UNZ+1+NG260002'
```

`edilint order.edi` reports:

```text
order.edi:1: error: [EL7007 edifact.service-string] UNA declares "/" as the decimal mark; EDIFACT allows only a period or a comma (type UNA)
```

## How to fix

Emit the conventional service string advice, `UNA:+.? '`, unless the partner has specified different characters — in which case emit theirs, in the same fixed nine-character form.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL7007`, or for a repository by listing it under `disable:` in `.edilint.yml`.
