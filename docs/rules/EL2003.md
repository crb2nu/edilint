# EL2003 — terminator.x12-segment

| Class | Severity | Applies to |
|---|---|---|
| terminator | error | `x12` |

Segment is not closed by the segment terminator the ISA declared.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| TA1 | `TA105` | `004` | the segment terminator is invalid |
| TA1 | `TA105` | `023` | premature end of file, when the unterminated segment swallows the trailer |

## What it catches

An X12 segment that does not end with the segment terminator ISA declared in its final position. In a real interchange this means the file was cut short in transfer, or a generator wrote the last segment without flushing its terminator.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
GE*1*1~
IEA*1*000000001
```

The file ends immediately after the last record shown, with no terminator after it.

`edilint example.x12` reports:

```text
example.x12:7: error: [EL2003 terminator.x12-segment] segment IEA is not closed by the declared segment terminator '~'; the interchange appears truncated (record 7, segment IEA) https://crb2nu.github.io/edilint/rules/EL2003.html
```

## How to fix

Append the declared segment terminator to the segment. If several segments are affected, suspect a truncated transfer and resend the file rather than patching it. `edilint fix --write` closes a single unterminated final segment.

## When to suppress

There is no safe case: a segment without its terminator runs into the next one, so the parse is wrong from that point forward.

Suppress the rule for a run with `edilint --disable EL2003`, or for a repository by listing it under `disable:` in `.edilint.yml`.
