# EL6003 — hl7batch.message-count

| Class | Severity | Applies to |
|---|---|---|
| hl7batch | error | `hl7v2` |

BTS-1 does not match the recounted MSH messages in the batch. An empty BTS-1 is not checked; the field is optional.

## What it catches

A BTS-1 that disagrees with the number of MSH messages in the batch. An empty BTS-1 is not checked, because the field is optional; a populated one is a promise the receiver reconciles against.

## Example

`batch.hl7`:

```text
FHS|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000|||NGFILE0001
BHS|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000|||NGBATCH0001
MSH|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000||ADT^A08|NGMSG0001|P|2.5.1
PID|1||NGH900000001^^^NORTHGATE^MR||RIVERA^DANA
BTS|4
FTS|1
```

`edilint batch.hl7` reports:

```text
batch.hl7:5: error: [EL6003 hl7batch.message-count] BTS-1 declares 4 message(s) (MSH) but the batch contains 1 (record 5, segment BTS) https://crb2nu.github.io/edilint/rules/EL6003.html
```

## How to fix

Recount the MSH segments in the batch and write that number into BTS-1, after confirming no message was dropped. `edilint fix --write` rewrites BTS-1 to the recounted value.

## When to suppress

There is no safe case for a populated count. Leave BTS-1 empty instead if the sending system cannot produce a reliable one.

Suppress the rule for a run with `edilint --disable EL6003`, or for a repository by listing it under `disable:` in `.edilint.yml`.
