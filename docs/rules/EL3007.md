# EL3007 — envelope.group-count

| Class | Severity | Applies to |
|---|---|---|
| envelope | error | `x12` |

GE01 does not match the recounted transaction sets in the group.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| 999 | `AK905` | `5` | number of included transaction sets does not match the actual count |

## What it catches

A GE01 that disagrees with the number of ST segments in the functional group. It usually means a transaction set was filtered out downstream of whatever wrote the group trailer.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
GE*4*1~
IEA*1*000000001~
```

`edilint example.x12` reports:

```text
example.x12:6: error: [EL3007 envelope.group-count] GE01 declares 4 transaction set(s) (ST) but the file contains 1 (record 6, segment GE) https://crb2nu.github.io/edilint/rules/EL3007.html
```

## How to fix

Recount the ST segments in the group and write that number into GE01. `edilint fix --write` rewrites it to the recounted value.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL3007`, or for a repository by listing it under `disable:` in `.edilint.yml`.
