charset / error

EL1005

charset.homoglyph

Applies to: all

What it catches and why it matters

Unicode character that is visually identical to an ASCII one, such as Cyrillic А for A.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

N1*PR*АCME~  (the first letter is Cyrillic U+0410, not Latin A)

How to fix it

Confirm the intended value with the source. For accidental lookalikes, preview edilint fix --unsafe, which proposes substitutions; inspect the diff before adding --write.

False positives and limits

A legitimate name in another alphabet may contain a character resembling an ASCII letter. Do not transliterate names merely to clear a warning. The unsafe fix tier requires deliberate review.

Acknowledgments and suppression

No X12 acknowledgment code names this defect; it is caught by the parser or the hygiene layer before an acknowledgment is produced.
Suppress the rule with --disable EL1005, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
