# EL3012 — envelope.trailing-data

| Class | Severity | Applies to |
|---|---|---|
| envelope | error | `x12` |

Segments appear outside any interchange.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| TA1 | `TA105` | `022` | invalid control structure, for segments after the IEA |

## What it catches

Segments sitting outside any interchange — before the first ISA or after the last IEA. Trailing data is usually a log line, a shell banner or a second file's fragment that a redirect appended to the interchange.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
GE*1*1~
IEA*1*000000001~
REF*BM*NG77001~
```

`edilint example.x12` reports:

```text
example.x12:8: error: [EL3012 envelope.trailing-data] segment REF appears outside any interchange; data after IEA is not part of a valid X12 file (record 8, segment REF)
```

## How to fix

Remove whatever follows IEA. If the extra segments are real content, they belong in their own interchange with their own envelope.

## When to suppress

There is no safe case; a receiver will either reject the file or ignore the content, and neither is what the sender intended.

Suppress the rule for a run with `edilint --disable EL3012`, or for a repository by listing it under `disable:` in `.edilint.yml`.
