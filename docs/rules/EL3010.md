# EL3010 — envelope.datetime

| Class | Severity | Applies to |
|---|---|---|
| envelope | error | `x12` |

ISA09/GS04 dates or ISA10/GS05 times are not valid YYMMDD, CCYYMMDD or HHMM[SS[DD]] values.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| TA1 | `TA105` | `014` | invalid interchange date value |
| TA1 | `TA105` | `015` | invalid interchange time value |
| 999 | `AK905` | `30` | invalid group date |
| 999 | `AK905` | `31` | invalid group time |

## What it catches

An envelope date or time that is not a valid value in its declared form: ISA09 and GS04 as YYMMDD or CCYYMMDD, ISA10 and GS05 as HHMM with optional seconds and hundredths. Impossible months and hours, and times one leading zero short, are the common shapes.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *261315*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
GE*1*1~
IEA*1*000000001~
```

`edilint example.x12` reports:

```text
example.x12:1: error: [EL3010 envelope.datetime] ISA09 is "261315": month 13 is out of range (expected YYMMDD) (record 1, segment ISA)
```

## How to fix

Write the date and time from a formatted timestamp rather than by string arithmetic. `edilint fix --write` restores a dropped leading zero in a time, which is the one case where the intended value is unambiguous.

## When to suppress

There is no safe case; the value is either a valid timestamp or it is not.

Suppress the rule for a run with `edilint --disable EL3010`, or for a repository by listing it under `disable:` in `.edilint.yml`.
