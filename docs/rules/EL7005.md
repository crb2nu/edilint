# EL7005 — edifact.interchange-count

| Class | Severity | Applies to |
|---|---|---|
| edifact | error | `edifact` |

UNZ-1 does not match the recounted messages in the interchange, or the recounted functional groups when UNG groups are used.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| CONTRL | `UCI.0085` | `29` | UNZ-1 differs from the received message or group count |
| CONTRL | `UCI.0085` | `13` | UNZ-1 is missing |
| CONTRL | `UCI.0085` | `37` | UNZ-1 contains letters where digits are required |

## What it catches

A UNZ-1 that disagrees with the interchange's contents: the number of messages when no UNG groups are used, or the number of functional groups when they are.

## Example

`order.edi`:

```text
UNA:+.? '
UNB+UNOA:4+NORTHGATEHEALTH+VALEMEDGROUP+260115:1430+NG260002'
UNH+NG0001+ORDERS:D:96A:UN'
BGM+220+NG77001+9'
UNT+3+NG0001'
UNZ+5+NG260002'
```

`edilint order.edi` reports:

```text
order.edi:6: error: [EL7005 edifact.interchange-count] UNZ-1 declares 5 message(s) (UNH) but the interchange contains 1 (record 5, type UNZ) https://crb2nu.github.io/edilint/rules/EL7005.html
```

## How to fix

Recount whichever the interchange contains — messages or groups — and write that number into UNZ-1.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL7005`, or for a repository by listing it under `disable:` in `.edilint.yml`.
