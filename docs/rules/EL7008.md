# EL7008 — edifact.nesting

| Class | Severity | Applies to |
|---|---|---|
| edifact | error | `edifact` |

UNG or UNH appears outside the envelope that must enclose it, or no UNB is present in a file forced to the edifact format.

## What it catches

A UNG or UNH outside the envelope that must enclose it, and a file forced to the edifact format with no UNB at all. As in X12, the nesting is what tells a receiver which interchange a message belongs to.

## Example

`order.edi`:

```text
UNH+NG0001+ORDERS:D:96A:UN'
BGM+220+NG77001+9'
UNT+3+NG0001'
```

`edilint --format edifact order.edi` reports:

```text
order.edi:1: error: [EL7008 edifact.nesting] no UNB segment found; file cannot be read as an EDIFACT interchange
```

## How to fix

Wrap the messages in a UNB and UNZ. A file that starts at UNH is usually a payload that lost its envelope in an intermediate step.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL7008`, or for a repository by listing it under `disable:` in `.edilint.yml`.
