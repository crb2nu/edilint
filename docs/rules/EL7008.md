# EL7008 — edifact.nesting

| Class | Severity | Applies to |
|---|---|---|
| edifact | error | `edifact` |

UNG or UNH appears outside the envelope that must enclose it, an interchange mixes functional groups with ungrouped messages, or no UNB is present in a file forced to the edifact format.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| CONTRL | `UCI.0085` | `30` | functional groups and messages mixed at the same level in the interchange |

## What it catches

A UNG or UNH outside the envelope that must enclose it, an interchange that mixes UNG functional groups with messages outside any group, and a file forced to the edifact format with no UNB at all. As in X12, the nesting is what tells a receiver which interchange a message belongs to. An interchange carries either messages or functional groups at its top level, not both; the first record that mixes them is reported once per interchange.

## Example

`order.edi`:

```text
UNH+NG0001+ORDERS:D:96A:UN'
BGM+220+NG77001+9'
UNT+3+NG0001'
```

`edilint --format edifact order.edi` reports:

```text
order.edi:1: error: [EL7008 edifact.nesting] no UNB segment found; file cannot be read as an EDIFACT interchange https://crb2nu.github.io/edilint/rules/EL7008.html
```

## How to fix

Wrap the messages in a UNB and UNZ. A file that starts at UNH is usually a payload that lost its envelope in an intermediate step. In a mixed interchange, move the ungrouped messages into a UNG..UNE group, or split them into their own interchange.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL7008`, or for a repository by listing it under `disable:` in `.edilint.yml`.
