EL5002

layout.padding

Applies to: fixed (requires --layout)

What it catches and why it matters

A field's padding is unambiguously on the side opposite the one the layout declares.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

A width-5, right-aligned, space-padded field contains "AB   " instead of "   AB".

How to fix it

Apply padding on the side opposite the field's declared alignment. Fix the generator or update the layout if the alignment declaration is incorrect.

False positives and limits

Only unambiguous opposite-side padding is reported. Significant leading or trailing pad characters may be data rather than padding; inspect the field's meaning before changing them.

Acknowledgments and suppression

No direct acknowledgment code is mapped for this rule.
Suppress the rule with --disable EL5002, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
