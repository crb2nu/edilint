# EL3002 — envelope.nesting

| Class | Severity | Applies to |
|---|---|---|
| envelope | error | `x12` |

GS appears outside an ISA, or ST outside a GS.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| TA1 | `TA105` | `024` | invalid interchange content, for a GS outside any ISA |
| 999 | `IK502` | `18` | transaction set not in a functional group, for an ST outside any GS |

## What it catches

An envelope segment outside the envelope that must enclose it: GS with no open ISA, or ST with no open GS. The nesting is what tells a receiver which interchange and which functional group a transaction set belongs to, so a misplaced header leaves the transaction unaddressed.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
IEA*1*000000001~
```

`edilint example.x12` reports:

```text
example.x12:2: error: [EL3002 envelope.nesting] ST appears outside a GS functional group (record 2, segment ST)
```

## How to fix

Rebuild the envelope around the payload. A GS before its ISA is usually a concatenation accident — two files appended without their envelopes being merged.

## When to suppress

There is no safe case; the nesting is part of the X12 structure rather than a convention.

Suppress the rule for a run with `edilint --disable EL3002`, or for a repository by listing it under `disable:` in `.edilint.yml`.
