# EL2005 — terminator.x12-separator

| Class | Severity | Applies to |
|---|---|---|
| terminator | error | `x12` |

Declared separators collide with each other or are alphanumeric.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| TA1 | `TA105` | `026` | invalid data element separator |
| TA1 | `TA105` | `027` | invalid component element separator |
| TA1 | `TA105` | `032` | invalid repetition separator |
| TA1 | `TA105` | `004` | the segment terminator is invalid |

## What it catches

An ISA whose declared separators cannot be told apart: an element separator equal to the component separator or the repetition separator, or a separator that is alphanumeric and so indistinguishable from data. Every downstream element boundary depends on these four characters being distinct.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P**~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
GE*1*1~
IEA*1*000000001~
```

`edilint example.x12` reports:

```text
example.x12:1: error: [EL2005 terminator.x12-separator] element separator and sub-element separator are both "*"; the interchange cannot be tokenized unambiguously (record 1, segment ISA) https://crb2nu.github.io/edilint/rules/EL2005.html
```

## How to fix

Regenerate the envelope with distinct, non-alphanumeric separators. The conventional 005010 set is `*` for elements, `:` for components, `^` for repetition and `~` for segments.

## When to suppress

There is no safe case. A colliding separator makes the element boundaries ambiguous, so two conforming parsers can read the same segment differently.

Suppress the rule for a run with `edilint --disable EL2005`, or for a repository by listing it under `disable:` in `.edilint.yml`.
