EL7002

edifact.unopened

Applies to: edifact

What it catches and why it matters

UNZ, UNE or UNT appears without its matching header.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

UNT+2+1'  (no open UNH message)

How to fix it

Restore the missing header or remove an unintended duplicate trailer at the source. Check UNH/UNT, UNG/UNE, and UNB/UNZ pairing.

False positives and limits

A fragment extracted from the middle of a message can start with an unmatched trailer. Check the full interchange.

Acknowledgments and suppression

No direct acknowledgment code is mapped for this rule.
CONTRL references use syntax-error element 0085, not action element 0083. UCI, UCF and UCM report interchange, group and message service-segment errors respectively. A missing or unreadable header can prevent a valid CONTRL response. Truncation, orphaned envelopes and data outside an interchange have no single mapping here.
Sources: https://service.gefeg.com/jwg1/Archive/v3/mt/m01.htm https://service.gefeg.com/jwg1/Archive/cl/v3/21a/cl16.htm
Suppress the rule with --disable EL7002, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
Reference: https://crb2nu.github.io/edilint/rules/EL7002.html
