# EL1005 — charset.homoglyph

| Class | Severity | Applies to |
|---|---|---|
| charset | error | `all` |

Unicode character that is visually identical to an ASCII one, such as Cyrillic А for A.

## What it catches

Unicode characters that render identically to an ASCII one: Cyrillic А for A, Greek Ο for O, a full-width digit for its ASCII form. They come from data typed in a localized editor or pasted out of a document, and they make an identifier compare unequal while looking right in every report.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
N1*PR*NORTHG\u0410TE HEALTH~
SE*3*0001~
GE*1*1~
IEA*1*000000001~
```

The escape sequences above stand for the bytes the file holds literally.

`edilint example.x12` reports:

```text
example.x12:4:13: error: [EL1005 charset.homoglyph] U+0410 looks like ASCII "A" but is not; ASCII-expecting parsers will not match this value (record 4, segment N1) https://crb2nu.github.io/edilint/rules/EL1005.html
```

## How to fix

Replace the character with its ASCII lookalike. `edilint fix --unsafe` does the substitution, and because it rewrites content bytes on a visual judgment it is in the unsafe tier and always shows a diff.

## When to suppress

When the field legitimately carries non-Latin text — a patient name in Cyrillic, for instance — and the receiver accepts it. Restrict the suppression to that file; a homoglyph in a control number is always a defect.

Suppress the rule for a run with `edilint --disable EL1005`, or for a repository by listing it under `disable:` in `.edilint.yml`.
