# EL4003 — counts.missing-field

| Class | Severity | Applies to |
|---|---|---|
| counts | error | `all (requires --count-rule)` |

The declaring record has fewer fields than the count rule reads.

## What it catches

A declaring record with fewer fields than the count rule reads — the trailer exists but stops before the field index the rule points at. A trailer written without its optional fields produces this, as does a count rule configured against a newer layout than the file.

## Example

`eligibility.psv`:

```text
HDR|NORTHGATE HEALTH|20260115|ELIG
DTL|NGH900000001|RIVERA|DANA|19840322|F|PPO-GOLD|20260101|20261231
DTL|NGH900000042|OKONKWO|TERESA|19770915|F|PPO-GOLD|20260101|20261231
TRL
```

`edilint --count-rule TRL:2:DTL eligibility.psv` reports:

```text
eligibility.psv:4: error: [EL4003 counts.missing-field] count rule TRL:2:DTL: record has 1 field(s) but the rule reads field 2 (record 4)
```

## How to fix

Emit the trailer with all of its fields, or point the count rule at a field the trailer actually carries.

## When to suppress

When the trailer's count field is genuinely optional and its absence is not an error for that partner. Removing the count rule for that file says the same thing more clearly.

Suppress the rule for a run with `edilint --disable EL4003`, or for a repository by listing it under `disable:` in `.edilint.yml`.
