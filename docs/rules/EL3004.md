# EL3004 — envelope.unopened

| Class | Severity | Applies to |
|---|---|---|
| envelope | error | `x12` |

IEA, GE or SE appears without its header.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| TA1 | `TA105` | `022` | invalid control structure |
| 999 | `IK304` | `2` | unexpected segment |

## What it catches

A trailer with no matching header: IEA, GE or SE arriving while nothing of that kind is open. The usual cause is two interchanges concatenated so that one file's trailer follows the other's, or a split that cut between a header and its trailer.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
SE*3*0001~
GE*1*1~
IEA*1*000000001~
```

`edilint example.x12` reports:

```text
example.x12:6: error: [EL3004 envelope.unopened] SE appears without a preceding ST (record 6, segment SE) https://crb2nu.github.io/edilint/rules/EL3004.html
```

## How to fix

Split or rejoin the file so every trailer follows its own header. If the file was produced by concatenating interchanges, concatenate the payloads and write one envelope instead.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL3004`, or for a repository by listing it under `disable:` in `.edilint.yml`.
