# EL4101 — fields.count-outlier

| Class | Severity | Applies to |
|---|---|---|
| fields | error | `delimited, hl7v2 (warning)` |

A record carries a different number of fields from others of the same record type.

## What it catches

A record carrying a different number of fields from the other records of its type. The record type is taken from the first field by default, or from `--type-field n`. An unescaped delimiter inside a free-text field is the usual cause, and it shifts every field after it.

## Example

`eligibility.psv`:

```text
HDR|NORTHGATE HEALTH|20260115|ELIG
DTL|NGH900000001|RIVERA|DANA|19840322|F|PPO-GOLD|20260101|20261231
DTL|NGH900000042|OKONKWO|TERESA|19770915|F|PPO|GOLD|20260101|20261231
DTL|NGH900000108|BRENNAN|MICHAEL|19910204|M|HMO-CORE|20260201|20261231
TRL|3
```

`edilint --count-rule TRL:2:DTL eligibility.psv` reports:

```text
eligibility.psv:3: error: [EL4101 fields.count-outlier] record type "DTL" has 10 field(s) here but 9 in 2 of 3 record(s) of this type; a shifted field count moves every value after the break (record 3, type DTL)
```

## How to fix

Quote or escape the delimiter inside the offending field, or choose a delimiter the data cannot contain. Counting the fields of the reported record against a correct one shows where the shift starts.

## When to suppress

When a record type legitimately has optional trailing fields and the extract omits them. Disabling `fields.count-outlier` for that file is the usual arrangement.

Suppress the rule for a run with `edilint --disable EL4101`, or for a repository by listing it under `disable:` in `.edilint.yml`.
