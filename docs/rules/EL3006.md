# EL3006 — envelope.segment-count

| Class | Severity | Applies to |
|---|---|---|
| envelope | error | `x12` |

SE01 does not match the recounted segments from ST through SE inclusive.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| 999 | `IK502` | `4` | number of included segments does not match the actual count |

## What it catches

An SE01 that disagrees with the segments actually present between ST and SE, counting both. Receivers use it as a checksum on the transaction set, so a mismatch is often the first evidence that segments were dropped or duplicated in transit.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~
BPR*I*4250.75*C*ACH*CCP~
SE*9*0001~
GE*1*1~
IEA*1*000000001~
```

`edilint example.x12` reports:

```text
example.x12:5: error: [EL3006 envelope.segment-count] SE01 declares 9 segment(s) from ST through SE inclusive but the file contains 3 (record 5, segment SE) https://crb2nu.github.io/edilint/rules/EL3006.html
```

## How to fix

Recount the segments from ST through SE inclusive and write that number into SE01, but check first that the segments themselves are all present — a wrong count can be the symptom rather than the defect. `edilint fix --write` rewrites SE01 to the recounted value.

## When to suppress

There is no safe case; the count exists precisely to be checked.

Suppress the rule for a run with `edilint --disable EL3006`, or for a repository by listing it under `disable:` in `.edilint.yml`.
