# EL5002 — layout.padding

| Class | Severity | Applies to |
|---|---|---|
| layout | warning | `fixed (requires --layout)` |

A field's padding is unambiguously on the side opposite the one the layout declares.

## What it catches

A field padded on the side opposite the one the layout declares — a right-padded identifier arriving left-padded, for example. The rule only fires when the padding side is unambiguous, so a field that is full, or padded on both sides, is not reported.

## Example

`remit.json`:

```json
{
  "name": "remittance-detail",
  "fields": [
    {"name": "record_type", "width": 3},
    {"name": "member_id", "width": 12, "pad": "right"},
    {"name": "last_name", "width": 16, "pad": "right"},
    {"name": "paid_amount", "width": 10, "pad": "left", "padChar": "0"},
    {"name": "paid_date", "width": 8}
  ]
}
```

`remit.txt`:

```text
DTLNGH900000001RIVERA          000014400020260116
DTLNGH900000042         OKONKWO000028107520260116
```

`edilint --format fixed --layout remit.json remit.txt` reports:

```text
remit.txt:2: warning: [EL5002 layout.padding] field "last_name" (offset 15, width 16): value is right-aligned but the layout declares padding on the right (left-aligned) (record 2, type DTL)
```

## How to fix

Pad the field on the declared side. Left-padded numerics and right-padded alphanumerics are the usual convention; check which the receiver's layout specifies before changing the generator.

## When to suppress

When the receiver is known to trim the field on both sides, which makes the padding side cosmetic. It is a warning for that reason.

Suppress the rule for a run with `edilint --disable EL5002`, or for a repository by listing it under `disable:` in `.edilint.yml`.
