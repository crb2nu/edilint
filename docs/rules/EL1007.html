EL1007

charset.x12-basic

Applies to: x12 (requires --charset basic)

What it catches and why it matters

Character outside the X12 basic character set but inside the extended set. Off by default; the default profile is extended.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

With --charset basic: N1*PR*Acme~  (lowercase letters are outside the basic profile)

How to fix it

Use the receiver's agreed profile. If basic is required, correct the generator to emit permitted characters; if extended is accepted, use the default extended profile.

False positives and limits

The basic profile is opt-in. A file accepted under the extended profile can trigger this warning when checked with --charset basic.

Acknowledgments and suppression

A trading partner's front end reports this defect as:
  999 code 6 (IK403): invalid character in a data element, when the partner accepts only the basic set
Suppress the rule with --disable EL1007, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
