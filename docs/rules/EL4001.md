# EL4001 — counts.mismatch

| Class | Severity | Applies to |
|---|---|---|
| counts | error | `all (requires --count-rule)` |

A declared record count does not match the recounted total.

## What it catches

A trailer that declares a record count the file does not contain. The check is driven by `--count-rule recordPrefix:fieldIndex:countedPrefix`, so it applies to any line-oriented extract with a self-describing trailer, not only to a particular partner's layout.

## Example

`eligibility.psv`:

```text
HDR|NORTHGATE HEALTH|20260115|ELIG
DTL|NGH900000001|RIVERA|DANA|19840322|F|PPO-GOLD|20260101|20261231
DTL|NGH900000042|OKONKWO|TERESA|19770915|F|PPO-GOLD|20260101|20261231
TRL|4
```

`edilint --count-rule TRL:2:DTL eligibility.psv` reports:

```text
eligibility.psv:4: error: [EL4001 counts.mismatch] count rule TRL:2:DTL: field 2 declares 4 "DTL" record(s) but the file contains 2 (record 4, type TRL)
```

## How to fix

Find out which side is wrong before editing either. A count one short of the records present usually means a record was appended after the trailer was written; a count too high usually means a record was filtered out afterwards.

## When to suppress

When the declared field counts something other than what the rule points at — a total of dollars rather than of records, say. Correct the count rule rather than suppressing the finding.

Suppress the rule for a run with `edilint --disable EL4001`, or for a repository by listing it under `disable:` in `.edilint.yml`.
