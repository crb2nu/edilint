# EL7009 — edifact.trailing-data

| Class | Severity | Applies to |
|---|---|---|
| edifact | error | `edifact` |

Segments appear outside any interchange; data after UNZ is not part of a valid EDIFACT file.

## What it catches

Segments outside any interchange — before UNB or after UNZ. Data after UNZ is not part of a valid EDIFACT file, and it usually arrives from a redirect that appended a second file or a log line.

## Example

`order.edi`:

```text
UNA:+.? '
UNB+UNOA:4+NORTHGATEHEALTH+VALEMEDGROUP+260115:1430+NG260002'
UNH+NG0001+ORDERS:D:96A:UN'
BGM+220+NG77001+9'
UNT+3+NG0001'
UNZ+1+NG260002'
FTX+AAI+++THANK YOU'
```

`edilint order.edi` reports:

```text
order.edi:7: error: [EL7009 edifact.trailing-data] segment FTX appears outside any interchange; data after UNZ is not part of a valid EDIFACT file (record 6, type FTX) https://crb2nu.github.io/edilint/rules/EL7009.html
```

## How to fix

Remove whatever follows UNZ, or give it its own UNB and UNZ if it is real content.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL7009`, or for a repository by listing it under `disable:` in `.edilint.yml`.
