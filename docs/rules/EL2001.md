# EL2001 — terminator.mixed

| Class | Severity | Applies to |
|---|---|---|
| terminator | error | `hl7v2, delimited, fixed, text` |

File mixes CRLF, LF and CR line endings.

## What it catches

A file whose records do not all end the same way: CRLF on some lines, bare LF or bare CR on others. It is the signature of two generators appending to one stream, or of a file that crossed platforms through a transfer that translated only part of it.

## Example

`eligibility.psv`:

```text
HDR|NORTHGATE HEALTH|20260115|ELIG\r\n
DTL|NGH900000001|RIVERA|DANA|19840322|F|PPO-GOLD|20260101|20261231\n
DTL|NGH900000042|OKONKWO|TERESA|19770915|F|PPO-GOLD|20260101|20261231\r\n
```

The escape sequences above stand for the bytes the file holds literally.

`edilint eligibility.psv` reports:

```text
eligibility.psv:2: error: [EL2001 terminator.mixed] line ends with LF but the file predominantly uses CRLF (CRLF x2, LF x1); mixed line endings split records inconsistently across platforms (record 2, type DTL)
```

## How to fix

Rewrite the file with one line ending throughout, choosing the style the receiver expects. `edilint fix --write` normalizes to whichever style the file already uses for most of its records.

## When to suppress

There is no safe case. A reader that splits on one terminator will merge or truncate the records written with the other, so the inconsistency always changes what is parsed.

Suppress the rule for a run with `edilint --disable EL2001`, or for a repository by listing it under `disable:` in `.edilint.yml`.
