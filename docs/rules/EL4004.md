# EL4004 — counts.no-declaring-record

| Class | Severity | Applies to |
|---|---|---|
| counts | warning | `all (requires --count-rule)` |

No record matched the count rule's declaring prefix, so nothing was verified.

## What it catches

A count rule that matched nothing: no record in the file began with the declaring prefix, so no count was verified. The finding exists so that a configured check cannot quietly stop running — without it, a missing trailer looks the same as a clean file.

## Example

`eligibility.psv`:

```text
HDR|NORTHGATE HEALTH|20260115|ELIG
DTL|NGH900000001|RIVERA|DANA|19840322|F|PPO-GOLD|20260101|20261231
DTL|NGH900000042|OKONKWO|TERESA|19770915|F|PPO-GOLD|20260101|20261231
```

`edilint --count-rule TRL:2:DTL eligibility.psv` reports:

```text
eligibility.psv: warning: [EL4004 counts.no-declaring-record] count rule TRL:2:DTL: no "TRL" record was found, so the declared count of "DTL" records (2 present) was never verified
```

## How to fix

Confirm whether the trailer should be there. If the extract legitimately has no trailer, remove the count rule; if it should have one, the missing trailer is the defect the rule just found.

## When to suppress

When one count rule covers a set of files and only some of them carry that trailer. It is a warning rather than an error for exactly that case.

Suppress the rule for a run with `edilint --disable EL4004`, or for a repository by listing it under `disable:` in `.edilint.yml`.
