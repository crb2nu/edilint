# EL5001 — layout.length

| Class | Severity | Applies to |
|---|---|---|
| layout | error | `fixed (requires --layout)` |

Record length does not match the sum of the layout's field widths.

## What it catches

A fixed-width record whose length is not the sum of the layout's field widths. Every field after the point where the length went wrong is read from the wrong offset, so one short record misparses entirely rather than partially.

## Example

`remit.json`:

```json
{
  "name": "remittance-detail",
  "fields": [
    {"name": "record_type", "width": 3},
    {"name": "member_id", "width": 12, "pad": "right"},
    {"name": "last_name", "width": 16, "pad": "right"},
    {"name": "paid_amount", "width": 10, "pad": "left", "padChar": "0"},
    {"name": "paid_date", "width": 8}
  ]
}
```

`remit.txt`:

```text
DTLNGH900000001RIVERA          000014400020260116
DTLNGH900000200FAIRWEATHER     00000512002026011
```

`edilint --format fixed --layout remit.json remit.txt` reports:

```text
remit.txt:2: error: [EL5001 layout.length] record is 48 character(s) long but layout "remittance-detail" declares 49; field "paid_date" (offset 41, width 8) is truncated (record 2, type DTL)
```

## How to fix

Pad or trim the record to the declared length, after checking that the layout matches the version of the file you were sent. A whole file off by the same amount means the layout is stale, not the data.

## When to suppress

When the file carries several record types of different lengths and the layout describes only one of them. Lint those files per record type rather than suppressing the rule.

Suppress the rule for a run with `edilint --disable EL5001`, or for a repository by listing it under `disable:` in `.edilint.yml`.
