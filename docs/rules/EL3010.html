EL3010

envelope.datetime

Applies to: x12

What it catches and why it matters

ISA09/GS04 dates or ISA10/GS05 times are not valid YYMMDD, CCYYMMDD or HHMM[SS[DD]] values.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

ISA09 = 260231  (February 31); ISA10 = 930  (three-digit time)

How to fix it

Emit valid envelope dates and times in their required widths. edilint fix can zero-pad selected short times, but invalid calendar values must be corrected from the source.

False positives and limits

Partner-specific shorthand is still nonconforming to the checked envelope representation. Dates are checked structurally, not for business plausibility or freshness.

Acknowledgments and suppression

A trading partner's front end reports this defect as:
  TA1 code 014 (TA105): invalid interchange date value
  TA1 code 015 (TA105): invalid interchange time value
  999 code 30 (AK905): invalid group date
  999 code 31 (AK905): invalid group time
Suppress the rule with --disable EL3010, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
