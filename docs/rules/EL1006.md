# EL1006 — charset.nonascii

| Class | Severity | Applies to |
|---|---|---|
| charset | warning | `all` |

Non-ASCII character that is not a known lookalike.

## What it catches

Non-ASCII characters that are not known lookalikes: accented letters, currency symbols, typographic quotes and dashes. These are legal in many interchanges and illegal in others, which is why the rule is a warning — it exists so the character is a decision rather than a surprise at the receiver.

## Example

`eligibility.psv`:

```text
HDR|NORTHGATE HEALTH|20260115|ELIG
DTL|NGH900000001|RIVERA|DANÉ|19840322|F|PPO-GOLD|20260101|20261231
```

`edilint eligibility.psv` reports:

```text
eligibility.psv:2:28: warning: [EL1006 charset.nonascii] record contains 1 non-ASCII character(s) ("É") in content expected to be ASCII (record 2, type DTL) https://crb2nu.github.io/edilint/rules/EL1006.html
```

## How to fix

Transliterate the character to ASCII when the receiver's character set is restricted, or confirm the receiver accepts it and leave it. Typographic quotes and en dashes pasted from a word processor should normally be replaced.

## When to suppress

When the trading partner's specification accepts the full character set the file uses. Disabling `charset.nonascii` for that partner's files is the usual arrangement.

Suppress the rule for a run with `edilint --disable EL1006`, or for a repository by listing it under `disable:` in `.edilint.yml`.
