edifact / error

EL7001

edifact.unclosed

Applies to: edifact

What it catches and why it matters

UNB, UNG or UNH is never closed by a matching UNZ, UNE or UNT.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

UNH+1+INVOIC:D:96A:UN'  (inside UNB, but no UNT follows)

How to fix it

Restore the matching UNT, UNE, and UNZ trailers for open headers after confirming the export is complete. Recheck counts and control references.

False positives and limits

Message fragments and incomplete captures can lack closing envelopes. A bad service string or terminator can also hide an otherwise present trailer.

Acknowledgments and suppression

Related acknowledgment codes (apply only to the described defect):
  CONTRL code 13 (UCI.0085): UNZ is missing
  CONTRL code 13 (UCF.0085): UNE is missing
  CONTRL code 13 (UCM.0085): UNT is missing
CONTRL references use syntax-error element 0085, not action element 0083. UCI, UCF and UCM report interchange, group and message service-segment errors respectively. A missing or unreadable header can prevent a valid CONTRL response. Truncation, orphaned envelopes and data outside an interchange have no single mapping here.
Sources: https://service.gefeg.com/jwg1/Archive/v3/mt/m01.htm https://service.gefeg.com/jwg1/Archive/cl/v3/21a/cl16.htm
Suppress the rule with --disable EL7001, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
Reference: https://crb2nu.github.io/edilint/rules/EL7001.html
