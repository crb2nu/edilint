# EL6005 — hl7batch.separator

| Class | Severity | Applies to |
|---|---|---|
| hl7batch | error | `hl7v2` |

FHS, BHS and MSH headers disagree on the field separator or the encoding characters, or a header's encoding characters are malformed. Split-and-merge tooling reads every message with the first header's separators, so a disagreeing message is misparsed.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| ACK | `ERR-3` | `101` | a required field is absent, only when this finding reports empty MSH-2; other separator and batch-header defects need partner-specific handling |

## What it catches

Headers within one file that declare different field separators or different encoding characters, and headers whose encoding-characters field is malformed. Split-and-merge tooling parses every message in a file with the first header's separators, so a message that declares its own is read with the wrong ones and its fields come apart.

## Example

`batch.hl7`:

```text
FHS|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000|||NGFILE0001
BHS|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000|||NGBATCH0001
MSH|!~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000||ADT^A08|NGMSG0001|P|2.5.1
PID|1||NGH900000001^^^NORTHGATE^MR||RIVERA^DANA
BTS|1
FTS|1
```

`edilint batch.hl7` reports:

```text
batch.hl7:3: error: [EL6005 hl7batch.separator] MSH-2 is "!~\\&" but the file's first header (FHS on line 1) declares "^~\\&"; every header in a file must use the same encoding characters (record 3, segment MSH) https://crb2nu.github.io/edilint/rules/EL6005.html
```

## How to fix

Emit every FHS, BHS and MSH in a file with the same separator and encoding characters. A single message declaring something different usually means it was merged in from another source without being re-encoded.

## When to suppress

There is no safe case. The whole point of the declaration is that one file parses one way.

Suppress the rule for a run with `edilint --disable EL6005`, or for a repository by listing it under `disable:` in `.edilint.yml`.
