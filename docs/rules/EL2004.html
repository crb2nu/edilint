terminator / warning

EL2004

terminator.x12-padding

Applies to: x12

What it catches and why it matters

Whitespace between segment terminators is applied inconsistently.

Failing example

These synthetic fragments illustrate the defect; they are not complete interchange files. Backslash escapes name bytes such as \r (CR) and \n (LF).

GS*...~\nST*...~SE*...~\nGE*...~

How to fix it

Use edilint fmt for consistent segment-per-line output, or preview edilint fix to normalize padding to the dominant style.

False positives and limits

Many X12 readers ignore inter-segment whitespace. This warning catches inconsistent serialization; the majority style may not be the partner's required style.

Acknowledgments and suppression

A trading partner's front end reports this defect as:
  999 code 1 (IK304): unrecognized segment identifier, because the padding is read as part of the next segment's identifier
Suppress the rule with --disable EL2004, or list it under "disable" in .edilint.yml. To accept the occurrences a file already has without suppressing the rule, record them with --write-baseline and run with --baseline.
