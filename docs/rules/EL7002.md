# EL7002 — edifact.unopened

| Class | Severity | Applies to |
|---|---|---|
| edifact | error | `edifact` |

UNZ, UNE or UNT appears without its matching header.

## What it catches

A UNZ, UNE or UNT arriving with no matching header open. Concatenated interchanges and mis-split files both produce a trailer that closes nothing.

## Example

`order.edi`:

```text
UNA:+.? '
UNB+UNOA:4+NORTHGATEHEALTH+VALEMEDGROUP+260115:1430+NG260002'
UNH+NG0001+ORDERS:D:96A:UN'
BGM+220+NG77001+9'
UNT+3+NG0001'
UNT+3+NG0001'
UNZ+1+NG260002'
```

`edilint order.edi` reports:

```text
order.edi:6: error: [EL7002 edifact.unopened] UNT appears without a preceding UNH (record 5, type UNT)
```

## How to fix

Split or rejoin the file so each trailer follows its own header.

## When to suppress

There is no safe case.

Suppress the rule for a run with `edilint --disable EL7002`, or for a repository by listing it under `disable:` in `.edilint.yml`.
