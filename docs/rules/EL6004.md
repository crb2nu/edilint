# EL6004 — hl7batch.batch-count

| Class | Severity | Applies to |
|---|---|---|
| hl7batch | error | `hl7v2` |

FTS-1 does not match the recounted BHS batches in the file. An empty FTS-1 is not checked; the field is optional.

## What it catches

An FTS-1 that disagrees with the number of BHS batches in the file. As with the message count, an empty FTS-1 is not checked.

## Example

`batch.hl7`:

```text
FHS|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000|||NGFILE0001
BHS|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000|||NGBATCH0001
MSH|^~\&|NORTHGATEHEALTH|NGCLINIC|VALEMEDGROUP|VMOFFICE|20260115143000||ADT^A08|NGMSG0001|P|2.5.1
PID|1||NGH900000001^^^NORTHGATE^MR||RIVERA^DANA
BTS|1
FTS|3
```

`edilint batch.hl7` reports:

```text
batch.hl7:6: error: [EL6004 hl7batch.batch-count] FTS-1 declares 3 batch(es) (BHS) but the file contains 1 (record 6, segment FTS)
```

## How to fix

Recount the BHS segments and write that number into FTS-1. `edilint fix --write` rewrites it to the recounted value.

## When to suppress

There is no safe case for a populated count.

Suppress the rule for a run with `edilint --disable EL6004`, or for a repository by listing it under `disable:` in `.edilint.yml`.
