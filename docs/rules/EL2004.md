# EL2004 — terminator.x12-padding

| Class | Severity | Applies to |
|---|---|---|
| terminator | warning | `x12` |

Whitespace between segment terminators is applied inconsistently.

Trading partners report this defect with:

| Acknowledgment | Element | Code | Meaning |
|---|---|---|---|
| 999 | `IK304` | `1` | unrecognized segment identifier, because the padding is read as part of the next segment's identifier |

## What it catches

Whitespace between segment terminators applied to some segments but not others — a file that puts a line break after most segments and runs two of them together. Both forms are legal on their own; the mixture usually means two generators wrote into one stream.

## Example

`example.x12`:

```text
ISA*00*          *00*          *ZZ*NORTHGATEHEALTH*ZZ*VALEMEDGROUP   *260115*1430*^*00501*000000001*0*P*:~
GS*HP*NORTHGATEHEALTH*VALEMEDGROUP*20260115*1430*1*X*005010X221A1~
ST*835*0001~BPR*I*4250.75*C*ACH*CCP~
SE*3*0001~
GE*1*1~
IEA*1*000000001~
```

`edilint example.x12` reports:

```text
example.x12:3: warning: [EL2004 terminator.x12-padding] segment ST is followed by nothing where the file predominantly uses LF (LF x5, nothing x1); inconsistent inter-segment whitespace breaks readers that split on the terminator plus newline (record 3, segment ST) https://crb2nu.github.io/edilint/rules/EL2004.html
```

## How to fix

Rewrite the interchange with one convention throughout. `edilint fmt --write` produces the canonical one-segment-per-line layout, and `edilint fix --write` aligns the stragglers with the padding the file already prefers.

## When to suppress

When the receiver is indifferent to segment padding, which most are. It is a warning because it predicts a generator bug rather than a parse failure.

Suppress the rule for a run with `edilint --disable EL2004`, or for a repository by listing it under `disable:` in `.edilint.yml`.
